# Пройденные темы

Полный архив пройденного. **В правила не загружается никогда**, поэтому растёт сколько угодно.
Учитель находит тему поиском: `python learner/covered.py <слово>`.

Формат одной темы: заголовок `## Тема`, строка с датой и файлом карточек, потом пункты-словарь:
`- понятие — что про него разобрали` одной-двумя фразами, чтобы через полгода по строке
восстанавливался механизм, а не только название темы.

Архив решает один вопрос: проходили тему или нет. Формулировки в нём — ориентир, а не истина
в последней инстанции: если запись расходится с кодом, прав код.

## Первая программа Go: запуск, пакеты и точка входа
2026-11-16 · карточки: не создавались
- первая программа — Алекс создал файл в practice/hello/, написал вывод двух строк и успешно запустил программу; в решении использовал один fmt.Println со знаком переноса строки \n
- go run — компилирует исходный код в машинный и запускает программу; первый запуск выполнен командой go run practice/hello/main.go
- package — каждый файл Go объявляет принадлежность к пакету; пакет объединяет файлы в одну часть программы, обычно в одной папке, и позволяет делить код на используемые части
- пакет fmt — стандартный пакет форматирования и вывода; import "fmt" подключает его, fmt.Println вызывает его функцию и добавляет перевод строки в конце
- package main и func main — для запускаемой программы нужны оба имени: пакет main обозначает запускаемый пакет, функция main служит точкой входа в код; обычная функция не вызывается автоматически после объявления
- имя файла — main.go не обязательно: Алекс переименовал файл в hello.go и успешно запустил его, сохранив package main и func main
- произвольные имена — пакет baz и функция buz допустимы как обычные имена, но не заменяют запускаемый пакет main и его функцию main; конкретные правила подключения собственных пакетов ещё не разбирались
- вызовы функций — выполнение начинается с main, которая может вызвать другую функцию; Алекс верно объяснил порядок и необходимость точки входа
