# Персонализация

Hermes в этом репозитории настроен под одного конкретного человека и один курс. Этот файл — карта: **где именно зашита персонализация и как её менять**. Он написан сразу для двоих: для тебя и для ИИ-агента, которому ты поручишь правки.

## Как менять

Правила меняет **не учитель**. Hermes, запущенный из папки `Hermes/`, свои правила трогать не имеет права — так он не теряет форму посреди урока. Правки делает обычный агент, запущенный **в корне репозитория**:

```bash
codex
```

Дальше вставляешь один из промптов ниже. Агент читает этот файл, правит нужные места и прогоняет проверку. После этого запускаешь учителя как обычно.

Есть три уровня глубины:

| Уровень | Что меняется | Сколько правок |
|---|---|---|
| **1. Ты** | кто ученик, обращение, тон | 2–3 абзаца и профиль |
| **2. Другой язык программирования** | цель курса, примеры, практика, проверки | все файлы правил, но по шаблону |
| **3. Не программирование** | то же плюс отказ от кода и автопроверок | самая глубокая переделка |

## Промпты

Впиши своё в угловые скобки и вставь целиком.

### №1. Настроить под себя — с этого начинают

```text
Прочитай PERSONALIZE.md в корне репозитория целиком и следуй разделу «Правила для агента».

Перенастрой учителя Hermes под меня:
- Кто я: <возраст, профессия, чем занимаюсь>
- Чему хочу научиться и зачем: <цель одним-двумя предложениями>
- Что уже знаю по теме: <ничего / основы / работал с ...>
- Опыт в программировании: <нет / какой>
- Как ко мне обращаться: <по имени / на «ты» / на «вы»>
- Мой компьютер: <macOS / Windows / Linux>, движок: <Codex / Claude Code / Antigravity>

Сначала определи уровень правок по карте (1, 2 или 3) и покажи мне список файлов, которые собираешься менять, с одной строкой «что и зачем» на каждый. Дождись моего «да». После правок запусти проверку и покажи результат.
```

### №2. Сменить язык программирования

```text
Прочитай PERSONALIZE.md целиком и следуй разделу «Правила для агента».

Переведи курс Hermes с Go на <язык>. Цель курса: <например, «джун-разработчик на Python за год»>.
Это уровень 2 по карте. Пройди все строки карты с пометкой «уровень 2»: замени примеры кода,
эталонный шаг, эталонные карточки, формат и запуск практических задач, список разрешённых команд
и проверку окружения. Сохрани структуру разделов и все инварианты. Сначала покажи план по файлам.
```

### №3. Учить не программирование

```text
Прочитай PERSONALIZE.md целиком и следуй разделу «Правила для агента».

Я хочу учить <предмет: английский, историю, бухгалтерию, …>. Цель: <зачем>.
Это уровень 3 по карте. Правило «код в каждом шаге» замени на «пример или упражнение в каждом шаге»,
придумай, что в этом предмете честно считается практикой и как её проверять без автотестов,
убери из проверки окружения всё про Go, Docker и PostgreSQL. Память, карточки, форма урока и
три уровня знаний остаются как есть. Сначала покажи план по файлам и жди моего «да».
```

### №4. Только обращение и тон

```text
Прочитай PERSONALIZE.md целиком и следуй разделу «Правила для агента».

Поменяй только обращение и тон: вместо «Сэр» обращайся ко мне <как>, на <«ты» / «вы»>.
Тон: <например, «спокойный, без шуток»>. Это строки карты с пометкой «обращение». Больше ничего не трогай.
```

### №5. Оставить один движок

```text
Прочитай PERSONALIZE.md целиком и следуй разделу «Правила для агента».

Я пользуюсь только <Codex / Claude Code / Antigravity>. Покажи, какие файлы относятся к другим
движкам и что сломается в проверке, если их убрать. Ничего не удаляй сам: дай мне список
и поправь проверку так, чтобы она не требовала убранных файлов.
```

### №6. Проверить, что ничего не сломалось

```text
Прочитай раздел «Правила для агента» в PERSONALIZE.md. Запусти проверку из папки Hermes/
и пройди по списку «что проверить после правок». Ничего не исправляй: покажи, что нашёл.
```

## Карта: что где зашито

Пути даны от папки `Hermes/`. Правила существуют в двух вариантах, и **править нужно оба**, если пользуешься обоими движками:

- `rules-claude/` — для Codex и Claude Code;
- `rules/` и `.agents/rules/` — облегчённый вариант для Antigravity (Gemini).

### Кто ученик

| Где | Что там сейчас | Уровень |
|---|---|---|
| `learner/profile.md` | Шаблон: «профиль не заполнен, начни со знакомства». Учитель заполнит его сам на первой сессии | 1 |
| `rules-claude/teaching.md`, 2-й абзац; `rules/teaching.md`, 2-й абзац | «The learner is a 4th-year IT student. Goal: junior Go backend developer…» — кто ученик и цель курса | 1 |
| там же, абзац **Main language: Go** | Биография автора: перешёл с Python на Go, мыслит моделью памяти из C. Отсюда правило «мостиков» к Python и C | 1 |
| там же, абзац **Always write to the learner in Russian** | Язык общения и обращение «Сэр» / «Сир» как взаимная шутка | обращение |
| `rules-claude/teaching.md`, раздел 0 **The learner's mantra** | Цитата автора о том, как он усваивает материал. На ней стоит вся система; менять формулировку стоит, только если тебе она не подходит | 1 |
| `rules-claude/teaching.md`, раздел 6 | Пример связки с пройденным: «как с PyLongObject» — из прошлого автора | 1 |
| `rules-claude/dialogue.md`, раздел 10 **Tone** | Тон: на равных, без лести, юмор в ответ на юмор | обращение |

### Цель курса и мерило важности

| Где | Что там сейчас | Уровень |
|---|---|---|
| `teaching.md`, раздел 1 **Three tiers** | Мерило «спросят на собеседовании джуна–мидла или встретится в первый год работы». Примеры трёх уровней — из сетей и Go | 2 |
| `teaching.md`, раздел 2 | «Связка с работой бэкендера и фраза для собеседования обязательны в каждой теме» | 2 |
| `cards.md`, раздел 1 | Карточка «как коротко ответить на собесе» в конце каждого модуля | 2 |
| `practice.md`, раздел 2 | «Практика — то, что бэкенд-разработчик реально делает на работе» | 2 |

### Язык программирования и примеры

| Где | Что там сейчас | Уровень |
|---|---|---|
| `teaching.md`, раздел 2 **Story moves**, раздел 2б, раздел 3 **Reference step**, раздел 4 | Все примеры и эталонный шаг — на Go (слайсы, `append`) | 2 |
| `dialogue.md`, разделы 8 и 11 | Правила про код и точность с примерами Go: `fmt.Printf`, версии Go, запрет на ассемблер | 2 |
| `style.md`, блок **Bad → good** | Примеры живого языка на материале Go | 2 |
| `cards.md`, разделы 2, 5, 6 | Пример файла карточек и эталонные карточки — Go и Unicode | 2 |
| `memory.md` и `AGENTS.override.md` | Пример записи в архив — «Слайсы и append» | 2 |

### Практика и окружение

| Где | Что там сейчас | Уровень |
|---|---|---|
| `practice.md`, разделы 3–5 | Формат задач: папка с `go.mod`, `task.go`, `task_test.go`; запуск `go test -C practice/<task>`; ревью-комментарии `// РЕВЬЮ:` | 2 |
| `practice.md`, раздел 4 | Фраза «Tasks up to 008 are old Python tasks» — наследие автора, в чистой копии таких задач нет. Нумерация начнётся с того номера, который учитель увидит в папке | 2 |
| `environment.md` | Go, драйвер `pgx`, PostgreSQL в Docker на порту 5433 | 2 |
| `practice/_infra/env.py`, `pg.py`, `docker-compose.yml` | Проверка окружения и база для практики | 2 |
| `.agents/skills/check/scripts/check.py`, блок 7 | `/check` даёт FAIL, если не найден Go, и WARN, если нет Docker | 2 |
| `.claude/settings.json` | Какие команды Claude Code выполняет без вопроса: `go test`, `go vet`, `go run` | 2 |
| `CLAUDE.md`, `AGENTS.override.md`, `GEMINI.md`, блок **Boundaries** | Список команд, которые учитель запускает сам, включая `go test` | 2 |

### Что в персонализации не участвует

Память (`learner/covered.py`, формат архива, потолки), Ivy, журнал тем, команды `/check`, `/end`, `/practice` и форма урока от предмета не зависят. Их трогают, только если сознательно меняют сам метод.

## Правила для агента, который правит репозиторий

Этот раздел адресован ИИ-агенту. Ты работаешь из корня репозитория и меняешь систему, а не ведёшь урок.

**Что нельзя ломать.** Эти вещи держат метод, а не вкус автора:

1. **Инвариант памяти.** Учитель не говорит «мы это проходили», пока не увидел тему в `profile.md`, `now.md` или в выводе `python learner/covered.py <слово>`. Нет в архиве — значит не учили.
2. **Форма урока.** Один шаг на сообщение; каждый шаг заканчивается действием ученика.
3. **Три уровня знаний.** Ядро учат полностью, деталь вплетают в шаг, остальное закрывают одной фразой и честно называют границу.
4. **Ошибки ученика нигде не записываются.** Не добавляй журналы ошибок и разделы «на что обращать внимание».
5. **Учитель не меняет свои правила.** Блоки **Boundaries** в точках входа остаются запретительными.

**Как править.**

- Правила написаны по-английски, речь для ученика и примеры — по-русски. Сохраняй это разделение.
- Меняй содержание примеров, но не их роль: эталонный шаг остаётся одним шагом с кодом и заданием в конце, эталонные карточки — по одной идее на карточку.
- Персоны под разные движки можно менять по отдельности. Если пользователь назвал один движок, правь его файлы и скажи, что остальные остались прежними.
- Факты об ученике клади в `learner/profile.md`, а не в правила: профиль общий для всех движков, а правила — нет. В правилах оставляй только то, что определяет курс.
- Точки входа `CLAUDE.md`, `GEMINI.md` и `AGENTS.override.md` дублируют инварианты намеренно. Меняешь инвариант — меняй во всех трёх.
- Codex не раскрывает импорты: в `AGENTS.override.md` не должно появиться строк вида `@файл`.
- Ничего не удаляй без явного «да» пользователя. Сначала план по файлам, потом правки.
- Не трогай `learner/covered.md`, `anki/`, `practice/` с решениями и `log/`: это состояние ученика.

**Лимиты размера.** За ними следит `/check`:

| Что | Лимит | Почему |
|---|---|---|
| `AGENTS.override.md` | 32 768 байт | сверх этого Codex молча обрезает инструкции |
| `GEMINI.md`, `AGENTS.md` и каждый файл в `.agents/rules/` вместе с импортами | 24 000 байт | лимит Antigravity на файл правил |
| `learner/profile.md` | 8 000 байт | грузится в каждый ответ |
| `learner/now.md` | 3 000 байт | грузится в каждый ответ |

**Что проверить после правок.**

1. Из папки `Hermes/` запусти `python .agents/skills/check/scripts/check.py` (на macOS и Linux — `python3`). В итоге не должно быть ни одного FAIL.
2. Поиском по `Hermes/` убедись, что не осталось упоминаний старой цели, старого языка и старого обращения там, где ты их менял.
3. Проверь, что обе персоны согласованы в том, что ты менял, или явно скажи пользователю, что вторая осталась прежней.
4. Коротко перечисли пользователю: какие файлы изменены, что в каждом, что осталось как было.
